# Saved places

*Design note for saved place lists. The contracts are
`packages/contracts/src/saved-list.ts` (operations in `operations.ts`, the
OpenAPI document regenerated by `bun run openapi`); the tables are
`saved_place_lists` and `saved_place_list_items` in
`packages/backend/src/db/schema/savedPlaces.ts`; every database access is
`packages/backend/src/db/places/savedPlacesRepository.ts`; the routes are
`packages/backend/src/routes/savedLists.ts`; the client is `goway.lists` in
`@goway.to/sdk`; the app is `packages/frontend/features/saved/` and
`lib/goway/saved.ts`.*

A person keeps private lists of places: "Saved", "Want to go", "Coffee,
ranked". A list holds **GoWay Place IDs** and the owner's own note about each;
nothing else.

## 1. Privacy

- **Personal data, owned by an Oxy user.** `owner_oxy_user_id` is the person's
  Oxy user id: no foreign key, no `users` table (Oxy owns identity). It is never
  published: the only reader of a list is its owner, so no response names
  anybody.
- **The person, not the session's account.** As for a review, the owner is the
  person behind the session (Oxy's actor chain). A session switched into an
  organization is `forbidden`: a list is personal, and the members of an
  organization must not read each other's.
- **Private only.** `SAVED_LIST_VISIBILITIES` is `['private']`, a CHECK holds the
  column to it, and there is no route that reads a list other than as its owner.
  Sharing is a later, reviewed widening of that one tuple plus an access rule,
  not a flag.
- **No location, no copy of a place.** A list stores a place id, a note, an
  ordering key and timestamps. A place's name, photo and hours are read from the
  place (`GET /places?ids=`), so a saved place is as fresh as the place, and
  where the person was when they saved it is not a thing the API can carry.
- **Nothing leaks into a place's history.** Saving writes no `place_revision`
  and appears in no public read of the place; a note is never in a revision.
  `saved lists` and `place_revisions` share no column and no write.
- **Not-found, never forbidden.** Somebody else's list, item or save answers
  `404 not_found`, the same as one that does not exist, on every read and every
  write. Ownership is part of the statement that touches the row (the repository
  has no "load by id, compare afterwards"), so a route that forgot to check
  would find nothing rather than leak.
- **Removable.** Deleting a list deletes its items (`ON DELETE CASCADE`).
  `deleteSavedDataOf(owner)` removes everything a person saved in one statement:
  the hook for an account erasure, so that path needs no knowledge of the schema.

## 2. The API

Every operation requires an Oxy session (`createOxyAuthMiddleware`) and is the
caller's own. Lists are `{ items, nextCursor }` with fingerprinted cursors
(`saved-lists`, and `saved-list-items` bound to the list id).

| | |
|---|---|
| `GET /lists` | your lists, oldest first |
| `POST /lists` | create; `201` |
| `PUT /lists/default` | your default "Saved" list, created with the given name when you have none; `201` created, `200` existed |
| `GET /lists/{listId}` · `PATCH` (rename) · `DELETE` (`204`) | one list |
| `GET /lists/{listId}/items` | its places in your order, keyset on `(position, id)` |
| `POST /lists/{listId}/items` | save a place at the end; `201`, or `200` with the existing item when it is already there |
| `PUT /lists/{listId}/items/order` | the named items go first in this order, the rest keep theirs; `204` |
| `PATCH /lists/{listId}/items/{itemId}` | set or clear (`null`) the note |
| `DELETE /lists/{listId}/items/{itemId}` | remove; `204` |
| `GET /saved-places?placeIds=` | which of your lists hold these places (at most 50), so a result can show a filled heart. Not a page: the request bounds it |

A list summary carries `itemCount` and `coverPlaceIds` (the first four places),
computed from the rows for the page being served, never stored.

### Limits (constants in `saved-list.ts`)

100 lists per person, 500 places per list, list names 1–80 characters, notes
1–500. Reaching one is `409 conflict` with `details.reason` one of
`name_taken`, `list_limit_reached`, `item_limit_reached`
(`SAVED_LIST_CONFLICT_REASONS`). List names are distinct per person, ignoring
case (a generated `name_normalized` and a unique index).

### The default list

`PUT /lists/default` is how a first save creates "Saved" lazily. The server
guarantees at most one default per person (a partial unique index, and the
owner's list writes are serialised on an advisory lock), so two devices saving
at once get one list. If the person already has a list of that name that is not
the default, it is adopted rather than clashed with. The name is the client's
(localized); the server never renames an existing list. The default is an
ordinary list afterwards: renameable, deletable, and made again by the next save.

### Places

`POST …/items` needs a published place: `404` for an id no place has, `410` for
one that was removed or merged (`details.mergedInto` names the survivor), as
every other place write answers. The list is checked first, so whether a place
exists is nobody's business who has no such list.

A **merge** of two places moves the absorbed place's saves to the survivor in
the merge's transaction (`moveSavedItemsToSurvivor`); a list that already held
the survivor just drops the duplicate. A place later **removed** stays in the
list (the list is the person's) and the app shows it as "No longer on GoWay"
with the usual remove control.

### Order

`position` is an ordering key, not an index: it rises from first to last,
removal leaves a gap, and only a reorder renumbers `0…n-1`, in one statement
inside a transaction that holds the list row. A reorder naming an item that is
not in the list changes nothing (`422`).

## 3. The app

- **Save** on a place opens the picker (`SavePlaceDialog`): a checkbox per list,
  an inline "New list". A person with no default list sees a "Saved" row that
  the server creates on that save. Signed out, the press goes through
  `useAuthGate` (the Oxy dialog opens over the map) and nothing else changes.
- **The heart** on a result row (`PlaceCard favorite / onFavoriteChange`) is the
  one-tap version: save to the default list, or remove from the only list that
  holds the place; with several, it opens the picker. Every heart on screen asks
  "is it saved?" through one batched `GET /saved-places` (`lib/goway/savedHolds.ts`).
  A row that picks a place for something else (a route stop) draws no heart.
- **`/saved`** lists the lists with `PlaceListCard`; **`/saved/<listId>`** shows
  one with `PlaceList` (move earlier/later, remove), the owner's notes, rename
  and delete. Pressing a place opens its note and the way to the map. The row is
  `placeRowCardProps`, the same card a search result is.
- Copy is in `lib/messages/saved.ts` (`en`, `es`, with the test that keeps the
  keys and placeholders aligned), like the products and Street 3D copy. A list's
  name and a note are the person's words and never translated.
- The fixture layer (`lib/goway/savedFixtures.ts`) answers the same routes with
  the same limits for development with no backend.

## 4. Not done, on purpose

Sharing and collaborators, a per-list colour or icon, moving a place between
lists, and syncing a list across devices in real time (a list is read when the
screen opens and after every write). Each is a change to the contract, so each is
reviewed as one.
